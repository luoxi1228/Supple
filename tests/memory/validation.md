# 内存峰值统计验证记录

本文保留测量时的旧 mode 编号：2/6/8/9 现对应 2/4/5/1。
复现脚本使用当前编号，原始测量记录不作改写。

验证环境：Linux x86-64，Intel Xeon Platinum 8369B，SGX SDK SIM；enclave 使用
`-O3` 和现有 SIM PIC/TLS 测试构建配置。硬件模式编译通过；环境没有 SGX
硬件设备，因此未进行 HW 运行测量。

## 正确性

- 生产计数器的精确字节测试通过：普通/零大小/对齐分配、嵌套分配 API、
  STL 扩容重叠、移动及原地 realloc、realloc 失败、异常清理、跨轮缓存、
  任意顺序释放、容量不足和计数溢出。失败结果保持无效。
- 现有宿主回归测试通过：2,952 个 FFOS_C 用例、1,840 个 FFOS_FR 用例。
  宿主测试用 `ASAN_OPTIONS=detect_leaks=0`；测试脚本启用 ASan/UBSan。
- 四种 mode 的真实 SGX ECALL、AES-GCM、PRB、Shuffle 及数据完整性验证通过。
  覆盖 `k=1`、`m*k<n`、`m*k=n`、`m*k>n`、三轮重复执行、非整除回退、
  空请求和错误 AES-GCM 标签。每种配置使用新 enclave。
- 实际 application 与实验脚本的完整 CSV 流程通过：正式峰值解析、MiB
  转换、旧文件备份、新文件追加、缺失峰值拒绝和独立 offline profile。
- 检查最终链接反汇编：SGX C++ `operator new` 和 AES-GCM 内部分配/释放
  调用到 `__wrap_malloc` / `__wrap_free`。

## 开销

参数：`n=16384, m=256, k=64, block_size=16`。每个 mode 运行五个 trial；
每个 trial 轮换无包装构建、包装但关闭采集、包装且开启采集三种设置。
每种设置使用独立 enclave，两轮预热、五轮正式执行，并验证全部输出。
表中为各 trial 正式轮次平均值的中位数，共 300 条正式轮次记录。

| Mode | 无包装 ECALL/ms | 包装但关闭/ms | 开启统计/ms | ECALL 增幅 | 算法 ptime 增幅 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2 / PSQF_SWO | 292.806 | 292.882 | 293.802 | 0.34% | 0.26% |
| 6 / FFOS_C | 87.282 | 87.745 | 88.527 | 1.43% | 2.79% |
| 8 / FFOS_FR | 89.579 | 89.717 | 89.813 | 0.26% | −0.05% |
| 9 / ShuffleBasedSWO | 371.156 | 373.269 | 377.254 | 1.64% | 1.60% |

增幅均相对无包装构建计算。微小负值属于运行噪声；这些结果只说明此
SIM 环境和参数下的实际开销，其他规模及 HW 模式需要在目标设备复测。
四种 mode 在这组参数下的 ECALL 和 ptime 增幅均低于 3% 优化目标。

最终实现使用适用于四种串行 mode 的全局作用域状态，避免每次分配/释放
进行 SIM TLS 查找。包装器只查询/更新固定地址表，不改变原始申请大小、
对齐或返回指针；调用原分配器期间暂停记录，避免计入分配器内部开销和
重复计算嵌套 API。表自身约占 256 KiB BSS，不进入算法堆峰值。

复现命令及无包装构建方法见 [README.md](README.md)。
