# Stage 06 batch routing review

Scope: the retained `batch_no_local` source change adds `FourGateSSE2.hpp`, specializes `ApplyFourIndependent` for the public 8-byte and 16-byte styles, and forces the existing unchecked cursor helpers inline. The stage 05 writer, fixed N=2/4/8 postorder schedule, storage representation, public validation, normalization, and membership routing are unchanged.

For each gate, let its two source records be x and y, and let its packed control be c in {0,1,2,3}. The existing OFork definition writes top = x XOR ((x XOR y) AND mask(c bit 1)), bottom = x XOR ((x XOR y) AND mask(c bit 0)). `Decode` broadcasts the packed byte and tests public bit positions {2,8,32,128} and {1,4,16,64}; a nonzero bit becomes an all-one 32-bit lane mask. For 8-byte records, unpack instructions duplicate each lane into one 64-bit mask. For 16-byte records, fixed shuffles broadcast the gate's lane across its record. Thus the four controls retain the original meanings: 00 copies x to both outputs; 01 retains x/y; 10 swaps to y/x; 11 copies y to both outputs. No control array is expanded.

The dispatch depends only on public record width, build architecture, and gate-run length. A contiguous run pairs first[g] with second[g] over publicly bounded disjoint halves. Four consecutive gates have eight distinct records and commute, so loading all four pairs before stores yields the same result as applying those four gates in the original order. The N=8 base case batches only its final gates (0,4), (1,5), (2,6), (3,7), after each half's four dependent gates have completed. The N=4 packet remains sequential because its gates share records. Odd runs and tails retain scalar gates. DFS's scalar routing and other public record-width specializations remain available.

Secret control values affect only the SIMD masks and selected payload bits. They do not choose branches, indices, source pointers, destination pointers, load/store widths, loop bounds, or allocation sizes. `CountFour` tests a pointer supplied from public compile configuration; it is not derived from gate data. All data loads precede stores for each independent pair/group. Loads/stores use fixed-size `memcpy`, which permits unaligned records without violating aliasing/alignment rules. The helper is enabled only for SSE2 x86-64 with ILP32 excluded. Other builds retain scalar/ASM fallback. The review establishes the source-level branch/address property for valid inputs; it is not a complete whole-program microarchitectural side-channel proof or a new assembly audit.

Packed cursor span checks still happen at each public application entry. Unchecked four-gate reads are used only when a public remaining-count test proves four controls remain. Cursor cache alignment branches depend on the public span offset and consumed gate count. Forced inlining changes compiler placement, not the cursor's behavior or access bounds. Packed trailing padding, shared-byte neighbors, and offset controls remain covered by regression tests.

Under default `COUNT_OSWAPS`, every batch adds exactly four to the same primitive counter; tails and dependent packets use the existing single-gate increments. The actual production ASM fixture asserts the canonical complete-network delta: N=8 has 12 gates, N=16 has 32, and N=32 has 80. Counter update aggregation preserves the observable final logical count but reduces the number of counter stores. The performance effect of that aggregation is not separately attributed because a consistent full-build counter-off experiment was not run.

The new kernel holds masks and four small payload groups in SIMD registers and allocates no workspace. It does not alter stage 04's public tile budget, narrow-counter thresholds/terminal checks, stack-frame limitations, or wide-row budget exception. Earlier stage 04/05 audits remain applicable. Full sanitizer/production-ASM regression and SGX SDK compilation of the exact retained candidate pass; parent-run final integration and SIM testing follow the production merge.
